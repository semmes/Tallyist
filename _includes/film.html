{%- comment -%} The home page's film: 30 seconds, rendered by code from the app's own screens, colours and measurements. Which file a reader gets is a media query on a , which a browser checks before it fetches anything, so each reader downloads one file or none. - The loop plays muted, only where the reader has not asked for reduced motion. Its first frame is its poster (the loop is cut to start 0.8 seconds in, on the counter), so it starts without a jump; the native controls pause it and turn the sound on. - When it plays is the site's one script, at the end of this file: from its first frame once half of it is on screen, paused once it scrolls away. It stores nothing and sends nothing, as the privacy page says, and scripts/check-links.py allows it by the hash of its text, so a change to it is reviewed like any other. Without it (or without JavaScript) the autoplay attribute still plays the film, by the browser's own rule: as soon as any of it is on screen, which under the hero is often at load. - With reduced motion asked for, the loop has no source at all and the player takes its place: the same film, which plays only when pressed. - Light and dark are separate films, like the screenshots; phones and narrow windows get 720p. HEVC first (Safari, and browsers with hardware HEVC), H.264 for everyone else. - The posters are CSS backgrounds, so only the one for the reader's appearance is fetched.
